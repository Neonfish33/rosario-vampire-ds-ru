# Какие трудности пришлось преодолеть

Проект начинался с готового английского патча (xdelta) и старого инструмента
tehwes. Ни спецификаций, ни исходников, ни полных данных от авторов не было —
почти всё пришлось восстанавливать самостоятельно.

## 1. Нет документации и «полурабочие» инструменты

- jjjewel выпустил только xdelta-патч; таблиц кодировок, скриптов сборки и
  описания форматов в открытом виде не было.
- Rosario Tool (tehwes) умеет BB/BAC/MPC, но:
  - **Import/Save молча не меняет файлы** — «repack» совпадал с оригиналом
    байт-в-байт;
  - шрифт не поддерживается вообще;
  - часть форматов описана лишь заметками.
- Поэтому пришлось написать собственный разбор и сборку MPC, а не полагаться
  на GUI.

## 2. MPC: структура и кодек

- Восстановлен заголовок, таблицы указателей `LC/LL/DS`, накопительные смещения
  **в кодах**, а не в байтах.
- Обнаружена нестандартная упаковка потока **3↔4 байта**
  (`enc(d0..d3)`), из-за которой обычное чтение u16 давало мусор.
- Разные диалекты терминаторов: `[EL]/[NL]` в `000` и `[EL2]/[NL2]` в `001–008`.
- Проверка: пересборка оригинала должна совпадать байт-в-байт; только после
  этого стали возможны вставки.

## 3. Шрифт `#FNT` — главная неизвестная

- Это **не NFTR**: стандартные NFTRedit/Kuriimu2 файл не открывают.
- Пришлось выяснить:
  - глиф 16×16 — четыре тайла 8×8, **4bpp**, младший ниббл слева,
    порядок TL, TR, BL, BR; `1` тело, `2` тень;
  - таблица глифов `(u16 0, u16 len, u32 offset)`, `len` включает заголовок LZ10;
  - ширины — 1 байт на глиф;
  - **offsets менять нельзя** — данные «переезжают», и вместо букв выводятся
    фрагменты; допустима только замена блобов по месту.
- **Баг LZ10-декодера игры**: ссылки копируются по 2 байта, поэтому `disp = 1`
  даёт мусор. Свой компрессор обязан держать `disp ≥ 2`.
- Игра делает искусственное «жирнение» (несколько копий со сдвигом), поэтому
  глифы должны быть тонкими (1 px), иначе счётчики букв закрываются.
- Полуширинные глифы занимают только левые тайлы.

## 4. Коды текста ↔ глифы

- Патч глифа №33 менял «A» — это подтвердило формат, но патчи соседних
  индексов ничего не меняли: порядок глифов не совпадает с кодами.
- Пришлось выяснить, что текст идёт через внутреннюю таблицу движка, и
  посадить кириллицу в слоты, которые реально используются (ASCII-диапазон),
  с собственной таблицей `rosario.tbl`.
- Без этого русские коды попадали в японские глифы (смесь кириллицы и иероглифов).

## 5. Переносы, ширина и редактура

- Бюджет строки — **228 px**; ширина символа берётся из таблицы ширин.
- Пришлось реализовать пересчёт переносов по словам/гласным и оптимальную
  точку `[NL2]`.
- ~280 длинных строк сокращены редактурой (иначе не влезали в бокс).
- Многоточие-лидеры (`…`) заменены на три точки: глиф в игре «плавает».

## 6. Отладка без отладчика

- Проверка шла через melonDS: запуск, клики/клавиши, захват окна, зум.
- Для поиска процедур использовались GDB-стабы и вотчпоинты
  (`tools/gdb_*.py` в рабочей папке), а также дифференциальные тесты
  («залить глиф — посмотреть, что изменилось»).
- Только после подтверждения «A → Ж» в живом ROM стало ясно, что формат верен.

## 7. Что осталось за пределами

- Плашки имён спикеров идут другим потоком — остаются латиницей.
- Меню/галерея — отдельные контейнеры (графика + MPC в NARC), не переводились.
- Часть сокращений — компромисс ради ширины строки.

Итог: вместо «взять готовый инструмент» пришлось восстановить контейнеры,
кодек текста, формат шрифта, собрать свой компрессор LZ10 и пайплайн
перевод → MPC → BB → ROM.
